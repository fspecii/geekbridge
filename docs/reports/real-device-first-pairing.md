# First pairing on a real phone: the link dropped after pairing

Seen on a Galaxy Z Fold5 (One UI, Android 14/15): pairing worked, the PC logged `connected`, then `link_lost: peer closed the connection` about a minute later (the phone closed it), and the computer never dialed back.

What changed:
1. **The computer reconnects by itself** (`bridge-service/src/reconnect.rs`, `Daemon::reconnect_tick`, every 2 s): a paired phone that announced itself in the last 20 s and has no link is dialed at its announced address. Back-off 2 s doubling to 60 s, at most 12 tries, a new address resets it; unpaired phones are never dialed; a manual `disconnect` is respected until the phone has been silent. `Status.reconnecting` feeds a "RETRYING / Reconnecting to your phone…" line on the desktop Home tile.
2. **A pairing in progress keeps the phone's link alive** (`AppState` pairing grace, 3 minutes): started when the pairing screen, the QR flow or any pairing code prompt (`LinkRuntime` observer) appears, it lets the foreground service run before any computer is paired, so locking the phone or switching to the PC window to compare the code no longer tears the link down. It ends after 3 minutes without a pairing.
3. **"Stay connected" is turned on explicitly at the first successful pairing** (`AppState.recordPaired`); the Home toggle still shows and undoes it. The service also starts when pairing begins, restarts its link on task removal (`onTaskRemoved`), re-announces on network change, and starts at boot (unchanged).
4. `CHANGE_NETWORK_STATE` is declared, a prerequisite of a `connectedDevice` foreground service on Android 14+. If the system refuses the service, Diagnostics now says so ("background service: not running (last start failed: …)") instead of failing silently.
5. Tests: `scripts/e2e/pair-background.sh` (emulator: pairing with HOME during and right after it, swipe from Recents, forced Doze; all PASS with the new APK), `lifecycle.rs` redial test, `reconnect.rs` unit tests, `ServicePolicy` pairing test. Not reproduced: on the emulator the previous APK also survived these steps, so the exact cause on the Fold5 is not proven; the grace period and the redial close the gaps found by reading the code. Samsung's battery settings can still stop a service; Diagnostics now shows its state.
