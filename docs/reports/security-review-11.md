# Security review 11: updater proxy and connect race, BlueZ guard, redial wake-ups, history queue, Android sort, uninstaller

Scope: the 27 commits after `850262c1c` (up to `origin/main` at `749747ffd`). Read: `bridge-update/src/http.rs`
(happy-eyeballs connect, `HTTPS_PROXY` CONNECT tunnel, `NO_PROXY`, clock message), `bridge-calls/src/setup.rs` (system
Bluetooth gate, adapter restore guard), the Do Not Disturb keep-warm thread and the privacy save path, `coexist.rs`
(`refresh_if_stale`), `reconnect.rs` (`wake`, `pause`, `idle_wait`), `phone_data.rs` (`pump_older`), on Android the SMS sort
and `UpdateModel.text()`, the consent store `.bak` change, `tray-disabled`, the uninstaller in `packaging/linux/install.sh`,
the `opt-level = "z"` profile entries, the base64 0.23 merge and `THIRD_PARTY_NOTICES.md`. Tests ran in temporary
directories only; nothing was run against the live service, a real control port, a real Bluetooth adapter or a device.

## Result in one paragraph

No remote weakness and nothing Medium or higher. Two Low defects fixed: a forgotten phone stayed in `share.json.bak`
(with its receive and auto-accept choices), and every unauthenticated discovery announcement woke the redial pass.
Residual risks (a proxy setting the updater cannot use means a direct connection; `write_atomic_plain` follows a planted
temp link) are listed at the end.

## Checked, no change needed

| Area | Finding |
| --- | --- |
| Header injection through proxy env values (`http.rs`) | `Proxy::parse` runs the value through `Url::parse`, which rejects every byte `<= 0x20` and `0x7f` (no CR, LF, space, NUL), credentials (`@`), a bad port and any path or query other than `/`. The proxy host is only used for name resolution and the TCP connect. The `CONNECT` line and `Host:` header carry the target authority, which comes from the already-validated, policy-allowed URL (`api.github.com` and the asset hosts), never from the environment. No header from the environment is written. |
| CONNECT tunnel | Only for `https` targets that are not loopback and not matched by `NO_PROXY`; TLS runs end to end against the bundled roots, so the proxy sees host and port only. The token is still sent only to the API host over TLS. Redirects re-enter `connect`, so each hop is re-checked against the policy and `NO_PROXY`. The reply is read byte by byte (nothing of the TLS stream is consumed), capped at 8 KiB, bounded by the overall deadline and the socket read timeout, and only `HTTP/1.x 2xx` with a three-digit code is accepted. Tests: endless header, silent proxy, `HTTP/1.1 2 OK`, `2000`, `ICY 200`, 407, garbage. |
| `NO_PROXY` matching | Suffix match is on a label boundary (`.{entry}`), so `notinternal.example` does not match `internal.example`. `host:port` is port-exact. A bare IPv6 (several colons) is not read as `host:port`; bracketed IPv6 works; `*:8080` and `:80` are not match-all; a bad port drops the entry. A hostile `NO_PROXY` can only make the updater go direct, which a process owner can do anyway. CIDR entries never match (documented). |
| Happy-eyeballs threads | At most `MAX_ATTEMPTS = 6` short threads per connect (`interleave` truncates), each bounded by `connect_timeout(min(remaining, io_timeout))`; losing sockets are closed when the channel receiver is dropped; the race returns at the deadline even when attempts hang (tested). Per request that is at most 6 threads per hop, and the redirect count is already bounded. A failed `spawn` is handled (continues with the other addresses, errors only when nothing is pending). DNS answers are attacker-influenced only by whoever controls the user's resolver. |
| Redirect allow-list, size and time limits | Unchanged by the diff: the policy is applied per hop, body cap and overall deadline are as before. The proxy path adds no body. |
| Clock-skew message | The new text replaces the text of rustls "certificate expired / not valid yet" errors with advice to check the clock. It does not relax verification. A server that really presents an expired certificate (or a middlebox) gets the same advice; the user is told to check the clock, and the update is still refused. |
| `system_bluetooth_blocked` | The gate only ever removes a capability: sandboxes and tests (`GEEKBRIDGE_STATE_DIR`, `GEEKBRIDGE_CONTROL_PORT`, `GEEKBRIDGE_NO_SYSTEM_BLUETOOTH`) cannot reach the real system-bus adapter, and an explicit `NO_SYSTEM_BLUETOOTH` beats `ALLOW_SYSTEM_BLUETOOTH=1`. It is a safety rail against tests, not an access control: anyone who can set the environment of the service or ctl runs as the user and can use `bluetoothctl` directly. A custom bus address (`Bus(Some)`) skips the gate on purpose (the fake BlueZ in tests). Child-process test covers `run`, `reconnect` and `forget`. |
| Command injection through device addresses | None: `setup.rs` talks to BlueZ over D-Bus (`zbus` method calls and property sets with typed values) and spawns no process. Addresses and paths are D-Bus values only. |
| Adapter restore guard | `AdapterGuard::drop` restores `Discoverable`, `DiscoverableTimeout` and `Pairable` in every exit (errors, `?`, panic, success), and powers the adapter off only when setup turned it on and did not reach pairing (`done` is set just before `connect_hfp`). The explicit restore after a failed `make_visible` runs twice with the guard (setting a value that is already there is harmless). Test: a setup that finds no phone leaves all three as it found them. |
| Keep-warm thread and privacy save | The deadlock fix is right: `enabled()` (which takes the privacy mutex) runs before the counter lock is taken, the counter guard is held only across the condvar wait, and `seen` is re-read from the same guard. No lost wake-up: the counter is compared under the lock the saver increments under. Lock order is `writer` then `chosen` in `set_with`, then the counter inside `choice_saved`; the keep-warm thread never holds the counter while taking `chosen`. A poisoned lock is recovered. Both regression tests cover the earlier hang. |
| Privacy file TOCTOU | `set_with` serialises writers with `self.writer`, builds `next` from the in-memory view under it, writes with `atomic_write_private` (O_EXCL temp, fsync, rename; reviewed in 10) and only then publishes. The file is read only at start. No window between check and use. |
| `coexist::refresh_if_stale` | No process is spawned: the probe is a session-bus `NameHasOwner` call on a socket the service opens itself. Nothing from a caller reaches an argument. One asker wins the `compare_exchange`, so a burst of `ClipboardStatus` requests starts one check, at most one per 20 s, and the asker waits at most 500 ms. The request needs the control token. Limitation: a probe that never returns would leave `CHECKED = u64::MAX` (answer stays as it was); a hang, not a security issue. |
| `reconnect.rs` wake and idle wait, dial rate | `wake`/`pause` only decide when the pass runs; whether a phone is dialled is still `Book::due`/`Fallback::due`: per-phone exponential back-off (to 60 s), 12 tries, and trust from the pairing store, so a spoofed announcement cannot make a redial storm. Announcements are already rate-limited per source (30 per 10 s, 4 ids per source, 256 sources). A burst of wakes is one `Notify` permit plus a 250 ms coalescing sleep, so at most four passes a second. `idle_wait` is bounded by 30 s and by `DEVICE_TTL_MS`. See defect 2 for the remaining wake-up cost. |
| `pump_older` | In-flight set is capped at 16 (stale after 15 s), the waiting queue at `MAX_THREADS` (300, `Busy` beyond), and entries are keyed by thread id (no request ids to reuse, a repeat ask moves the thread to the front instead of adding a second entry). Sends cannot exceed the number of waiting entries however a phone answers: an empty page clears the in-flight set, which only lets queued requests go out. The phone is a paired, consented peer, and the queue holds ids, not bodies, so hostile answers do not grow memory. `th.asked_older` is set before a send that can fail; the thread is re-queued at the front, so nothing is lost. |
| Android SMS and MMS sort | `QUERY_ARG_SQL_SORT_ORDER` is built by `newestFirstSql(Telephony.Sms.DATE, Telephony.Sms._ID)` from provider column constants only. No remote or user text reaches the sort; selection still uses `QUERY_ARG_SQL_SELECTION_ARGS`. `SmsSortTest` pins the string. The lazy status-handler thread only delays creating the thread. |
| `UpdateModel.text()` | `isNull(key)` is also true for a missing key, so the result is `""` for both; a JSON `null` is no longer the text `"null"`. That closes a small hole: `"tag_name": null` used to pass as the tag `"null"` and `"digest": null` was read as a string. Sizes, tag length and asset count limits are unchanged. Tests added. |
| `consent.json.bak` | Forgetting a phone now rewrites the backup with `save_and_refresh_backup` (same call the trust store uses): the id and its choices do not survive in the one-generation copy, and a damaged `consent.json` cannot bring the phone back. Test asserts the backup has no id. Other writers (grant, default) still keep the previous generation on purpose. See defect 1 for the sibling file that had the same gap. |
| `tray-disabled` | Written with `write_atomic_plain` (mode 0600, temp then rename, directory fsync) instead of `fs::write` (umask). Contents are empty. See residual risk 2. |
| Uninstaller | New lines only run caches tools on `$icondir`/`$appdir` and remove `icon-theme.cache` when no other file is left under the icon dir (`find` does not follow links; `index.theme` of a system `hicolor` counts as a file, so a shared theme keeps its cache) and `mimeinfo.cache` when it is the bare `[MIME Cache]` header. Both are regenerable caches and are removed with `rm -f` (a link is removed, never its target). The `rm -rf` calls are unchanged: only `"$updatedir"`/`"$statedir"` that match `/*/geekbridge` and are directories, under `--purge-data`; `rm -rf` on a path that is a link removes the link only. The download folder is explicitly left alone and the message says so. `[[ ... ]] && echo` as a list under `set -e` does not abort. |
| `opt-level = "z"` (zbus, zvariant, zbus_xml, x509-parser, rcgen, webpki-roots) | Size only; no source change. Because `cargo test` uses the dev profile, these entries are not exercised by the normal test run. Run for this review in the release profile (LTO off for speed): `cargo test --release -p bridge-kde` (119 unit tests incl. certificate generation, persistence, damaged-identity recovery, wrong-clock acceptance, certificate CN must equal device id, tampered certificate trusts nobody, wrong server certificate rejected) and `cargo test --release -p bridge-update` (the TLS client with webpki-roots): all pass. The release e2e pairing run covers the same code with the real LTO. |
| Dependencies, `THIRD_PARTY_NOTICES.md` | `Cargo.lock` diff is only the removal of `base64 0.22.1` (one version, 0.23.1, left; no new crate, no source change). Notices regenerated (479 crates, base64 0.22 sections gone). The new `realnet.rs` is `#[cfg(test)]`, `#[ignore]` and gated by `GEEKBRIDGE_REALNET`. |
| Other changes | `ctl` messages, doctor wording and hints, `callwifi` test rewrite (no wall-clock race), `link.rs` test tolerance, `daemon.rs` `refresh_if_stale().await` before the clipboard status, 30 s expiry housekeeping, `tick_alerts` without the blocking pool: no new input, no new privilege. |

## Defects fixed

| # | File:line | Severity | Finding and exploit | Fix |
| --- | --- | --- | --- | --- |
| 1 | `crates/bridge-service/src/share.rs` `SettingsWriter::persist` (called from `forget_device`) | Low | The `.bak` change in this range covered `consent.json` only. `share.json` keeps per-phone "receive" and "auto accept" choices, and unpairing rewrote it with a plain `save`, which copies the previous generation to `share.json.bak`. The forgotten phone's id and permissions stayed on disk, and if `share.json` was ever damaged the one-generation fallback restored them: a phone paired again under the same id (re-link) would then auto-accept files without the user opting in again. | `forget_device` persists with `refresh_backup = true` (`save_and_refresh_backup`). Test `a_forgotten_phone_is_not_kept_in_the_settings_backup`: an ordinary save keeps the older generation, a forget leaves no trace of the id. |
| 2 | `crates/bridge-service/src/lib.rs` `record_device` | Low | Every parsed announcement called `reconnect::wake()`, including repeats, ids that did not fit the full device list, and spoofs. The redial pass would not dial more often (back-off is per phone), but a LAN host could keep an idle service doing up to four passes a second (lock, device scan, sightings) indefinitely, which defeats the idle-wakeup budget the wake design is for (30 per 10 s per source, 256 sources are allowed through). | A wake only for a new device, a changed address or port, or a repeat of the same id more than 5 s after the last one (real phones announce every 30 s), never for an announcement dropped from a full list (`announcement_is_news`; test `repeat_announcements_do_not_wake_the_redial_pass_every_time`). |

## Residual risks (accepted)

1. **An unusable proxy setting means a direct connection.** `HTTPS_PROXY`/`ALL_PROXY` with `https://`, `socks5://`,
   credentials or a path is read as "no proxy" (documented in `http.rs` and `docs/updates.md`). A user who sets a SOCKS
   or authenticated proxy to hide their address would have the update check (one GET to `api.github.com`, no identifier)
   go out directly. Failing closed would stop updates for everyone who has `ALL_PROXY=socks5://...` exported for other
   tools, so it is left as is; a log line or a doctor note for an ignored proxy value is a possible follow-up.
2. **`write_atomic_plain` opens its temp file without `O_EXCL`** (`.<name>.tmp.<pid>`, `create + truncate`), so a link
   planted at that name by the same user would be written through. The state directory is `0700` and the file is empty
   for `tray-disabled`, so another user cannot plant it and the owner gains nothing. The private writers (reviewed in 10)
   already use `O_EXCL`; switching the plain one is a small follow-up.
3. **`opt-level = "z"` is not covered by the default CI test run** (dev profile). The release e2e jobs and a one-off
   release-profile run of `bridge-kde` and `bridge-update` (this review) cover certificate generation and validation.
4. **CIDR ranges in `NO_PROXY`** never match, so a corporate bypass list written as `10.0.0.0/8` still goes through the
   proxy (the safe direction).
5. **`cargo audit` and `cargo deny`** are not installed on the review machine; the CI `supply-chain` job remains the
   check. The lock diff contains no new crate.
